## The SSO proof (INT-1)

`servicedesk/tests/test_http_mode_sso.py` stands up **Service Desk in `AUTH_MODE=http`** against
a faked MM OS, with only the network boundary stubbed. Everything else is production code:

- a **real RS256 keypair** (self-generated by `backend/app/security` at import, pointed at a
  temp key file);
- the launch token is minted by the **production** `backend/app/security.mint_service_token`
  (loaded under a synthetic package name `mmos_backend` to avoid the `app` package-name clash
  between `backend/app` and `servicedesk/app`);
- verification runs through the **production client kit** `packages/mmos-client-py`
  (`MMOS._verify` → `_verify.verify_token`, the exact ordered checklist from docs/04);
- the accept/session handoff, the fail-closed allowlist middleware and the flat-error handler
  are the real `MMOS.install(app)`;
- the protected route is Service Desk's own `GET /api/tickets/mine`, guarded by the production
  `app.mmos_seam.get_current_user` http branch;
- the MM OS JWKS + revocation feed are injected via `httpx.MockTransport` — the same boundary
  every other suite fakes at. **No socket is opened.**

What the 8 tests assert (all mapping to the brief's a–d):

- **(a)** `POST /_mmos/session` with a valid launch token → 200 and sets the `servicedesk_mmos_at`
  session cookie; `GET /_mmos/accept` serves the handoff page.
- **(b)** with that cookie a protected route works (`GET /api/tickets/mine` → 200); the same
  token also works as a `Bearer` credential; no token → 401 `missing_token` (allowlist fails
  closed).
- **(c)** rejected with 401: **expired** (`expired`), **wrong audience** (a token minted for
  `itemcode` → `bad_audience`), **tampered signature** (`bad_signature`), and a token **signed by
  a different key but carrying the trusted kid** (`bad_signature`).
- **(d)** after the token's **jti** is added to the revocation feed and one `poller.poll_once()`
  runs (the same call the 60s background thread makes), the next request is `401 revoked` — proven
  offline, no MM OS round trip. A second test proves the same for **subject-level** revocation.

One faithful detail worth knowing: the kit sets the session cookie `Secure` (correct — Service
Desk runs behind TLS). An http `TestClient` would silently drop a `Secure` cookie from its jar,
so the test speaks **https** to the ASGI app (`base_url="https://testserver"`). That is the
honest mirror of the real deployment, not a workaround around the cookie flag.

## Assumptions

1. **The brief's literal finish command runs from the wrong directory.** `backend\.venv\Scripts\python.exe -m pytest backend/tests -q`
   executed from the repo root fails at collection with `ModuleNotFoundError: No module named 'app'`
   — `backend/tests/conftest.py` does `from app import models`, so pytest must run with `backend/`
   as the working directory (as `RESUME.md` and `handoff/a1-identity.md` both show:
   `cd backend && .venv/Scripts/python.exe -m pytest tests -q`). This is pre-existing (it fails the
   same way before any C1 change) and lives in the frozen conftest, so I did not touch it — I just
   ran the working form. Flagging so the number is trusted.
2. **INT-1 loads `backend/app` under a synthetic package name `mmos_backend`.** Both
   `backend/app` and `servicedesk/app` are packages literally named `app`, and the servicedesk
   conftest imports servicedesk's `app` first, so a plain `import app.security` would resolve to the
   wrong package. The test loads only the two backend modules it needs (`config`, `security`) via
   `importlib` under a distinct name; `security.py` uses only relative imports so this resolves
   cleanly. If backend later grows an absolute `import app.*` inside `security.py` or `config.py`,
   this loader would need revisiting — it does not today.
3. **`set_real_mmos_for_testing()` is the only production-code change for INT-1**, and it is inert
   in production: `get_real_mmos()` still builds the real instance lazily from `settings()`; the
   setter merely lets the test inject a `MockTransport`-backed instance and reset it to `None`
   afterward. No stub-mode test touches it.
4. **`deploy/docker-compose.yml` now uses `expose: 8000` instead of `ports:`.** The container
   still listens on 8000 (Dockerfile `EXPOSE` + the healthcheck) and Traefik reaches it over
   `mmos_internal`; `expose` documents the port without publishing it to the host. If some
   non-Coolify path genuinely needs a host port, bind it to loopback only (`127.0.0.1:8000:8000`),
   never `0.0.0.0` — but the whole point of B3's finding is that Traefik makes that unnecessary.
5. **`--workers 1` is now explicit at both serving entry points** (`deploy/entrypoint.sh` and the
   coolify compose inline command). It was previously only implicit (uvicorn's default is 1). The
   coolify compose overrides the entrypoint with its own inlined command, so it needed the flag
   too — setting it in only one place would have left the demo topology unprotected.
6. **`docs/14` marks the OAuth consent screen "Internal".** That is correct for a Workspace
   deployment and matches the code's day-1 path (PIN first, corporate Google linked on top). MM
   OS's code *also* allows a personal `gmail.com` to complete the **link** flow for an already
   provisioned user; if the owner later wants personal accounts to clear the Google consent layer
   too, that is a separate switch to External + Google verification, which the doc calls out but
   does not prescribe. `demo_seed.py` was **not** deleted (owner decides timing) — only documented
   for removal, per the brief.
